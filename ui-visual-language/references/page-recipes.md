# 页面配方

同样一套 token，页面结构错了照样不好看。本文件给节序、节奏与文案规则。

---

## 一、产品落地页

### 节序

| # | 区块 | 作用 | 高度预算 |
|---|---|---|---|
| 1 | 吸顶导航 | 建立"这是个产品"的第一判断 | 76px |
| 2 | Hero（eyebrow + 大标题 + 导语 + 双按钮 + 元信息） | 一句话说清是什么、给谁用 | 首屏 55–65% |
| 3 | 产品截图框 | 证明"已经能用"，截断质疑 | 首屏剩余 |
| 4 | 三条核心价值（横向等分） | 把功能翻译成结果 | 320–400px |
| 5 | 能力矩阵（2×2 或 3×2 卡片） | 承接"具体能干什么" | 600–800px |
| 6 | 架构 / 工作原理图 | 给技术决策者看的证据 | 500–700px |
| 7 | 安全 / 合规 / 权限 | 打消采购顾虑 | 400–600px |
| 8 | CTA 带 | 收口，唯一第二个主按钮 | 260–320px |
| 9 | 页脚 | 导航兜底 + 信任细节 | 320–400px |

**关键：第 2 和第 3 必须同屏出现。** 首屏只放标题不放产品图的页面，
会让访客必须滚动才能确认"这是软件还是咨询公司"——这一滚,流失就发生了。

### 节奏

- 区块上下内边距统一 64px；**相邻两个同色区块之间用 80px 且不加分隔线**，
  靠留白分区比画线高级。
- 每 2–3 个区块换一次背景（`--paper` → `#fff` → `--paper`），制造呼吸感。
  背景切换处加 `1px solid var(--line)` 或干脆不加，二选一，不要混用。
- 区块标题统一走三段网格（见 `components-content.md` 第 2 节），**不要居中**。
  居中标题连续出现 4 次以上，页面会显"模板感"。

### 文案规则

| 规则 | 反例 | 正例 |
|---|---|---|
| 标题说结果，不说功能 | 强大的权限管理系统 | 谁能改生产环境，一屏看清 |
| 动宾结构，一个逗号以内 | 我们提供基于角色的细粒度访问控制能力 | 按角色授权，改动留痕 |
| 数字优先 | 大幅提升效率 | 发布耗时从 40 分钟降到 3 分钟 |
| 导语 ≤ 60 字 | 长段落介绍公司愿景 | 一句话说清范围与收益 |
| 技术名词保留原文 | 容器编排平台 | Server + K8s |

标题里的关键词用 `<em>` 染主色，**每屏最多一处**。

## 二、文档站

```
┌ 吸顶导航 ──────────────────────────────┐
├ 移动端文档条（sticky，≤760px 出现）      │
├ 左栏目录 220px │ 正文 max 720px │ 右栏页内 TOC 200px
└ 底部上一篇 / 下一篇 ────────────────────┘
```

- 左栏：章节树，13px，当前项加 `--soft` 底 + 主色文字。
- 右栏：页内锚点，`sticky top: calc(var(--header-h) + 24px)`，2px 左描边指示进度。
- 正文：`15px / 1.9`，`max-width: 720px`；代码块 `#f5f7fc` 底、`10px` 圆角、
  不加外阴影。
- 代码块上方给语言标签与复制按钮，复制成功后按钮文案改为「已复制」并 1.5s 复位。
- **必须有的降级**：目录加载失败时显示「目录暂时无法加载 + 重试」，不要让整页空白。
- 移动端把两栏收进抽屉，正文 `100% - 32px`，代码块横向滚动而不换行。

## 三、下载页

| 区块 | 内容 |
|---|---|
| 顶部 | 版本号 + 发布日期 + 三条命令式入口（Linux / macOS / Windows Tab） |
| 主卡 | 一键安装命令（等宽字体 + 复制按钮），下面一行校验命令（`sha256sum`） |
| 表格 | 平台 / 架构 / 包大小 / 校验值 / 下载 |
| 侧栏 | 系统要求、升级说明、供应链安全提示（签名、校验来源） |

版本号必须**运行时从接口拉**（源站即如此），不要在 HTML 里写死——
写死的版本号三个月后就是一条错误信息。失败时显示「下载信息加载失败」+ 重试，
而不是展示一个过期版本。

## 四、博客 / 文章

- 列表：`日期 · 分类 · 标题 · 摘要（≤2 行，省略号）· 阅读时长`，行间 `1px` 分隔线，
  不用卡片。卡片列表在文章数 > 20 时视觉噪音过大。
- 详情：正文 `17px / 1.95`（阅读页比官网更松），`max-width: 700px`，
  首字下沉或无——二选一，不要都上。
- 文章页右侧固定「本文目录」，与文档站共用组件。

---

## 五、移动端折叠顺序

桌面横向排列的区块，在小屏**不要简单堆叠**，按信息重要性重排：

| 桌面 | 移动端顺序 |
|---|---|
| 左图右文 | 文 → 图（先读结论再看证据） |
| 三列卡片 | 保留 3 张，第 4 张起折叠为「展开更多」 |
| 表格 | 转成「标签 : 值」的键值列表，**不要横向滚动** |
| 页脚四列 | 手风琴或单列，品牌区置顶 |
| Hero 双按钮 | 主按钮全宽，次按钮全宽描边，文字链接居中 |

字号在 540px 处进入最小档：H1 `29px`、H2 `24px`、正文保持 `14–15px` 不缩。
**正文永远不要为了"适配"而缩到 13px 以下**——那是移动端阅读疲劳的主因。

## 六、自检：页面级

- [ ] 首屏同时出现标题和产品视觉？
- [ ] 区块背景最多用了 3 种色（paper / white / 一个浅渐变）？
- [ ] 每个区块的标题都用同一种对齐方式（建议全部左对齐三段式）？
- [ ] 全页主按钮不超过 3 个（首屏 1 + 中段 0–1 + 收口 1）？
- [ ] 任意两屏之间的留白是否一致，没有忽大忽小？
- [ ] 移动端 375px 宽度下无横向滚动条？
