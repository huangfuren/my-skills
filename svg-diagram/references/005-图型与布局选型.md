# 图型与布局选型

`002-布局与坐标.md` 给的是通用算法（等距排列、容器高度、文字居中、宽度预估）。
本文件解决它没覆盖的问题：**这张图应该用哪种布局**。

选错图型的代价比坐标算错更大——坐标错了能改，图型错了整张要重画。

画布尺寸按 `001-视觉规范.md` 第一节的两个模式选。

## 一、选型表

先确认"这张图要回答什么问题"，再定图型。不要先想"我要画个架构图"。

| 要回答的问题 | 图型 | 主布局 | 模式（画布宽） |
|---|---|---|---|
| 一堆资源分布在哪、每个是什么 | **分区全景图** | 双栏分区 + 区块容器 + 三行卡片 | B（1960） |
| 系统由哪些层组成、层间怎么调用 | 分层架构图 | 纵向分层，每层横排卡片 | A（1200） |
| 哪些节点/区域连通，怎么通 | 网络拓扑图 | 双栏分区 + 跨区连线 | A/B（1400/1960） |
| 一件事按什么顺序做、在哪判断 | 流程图 · 决策流 | 纵向主线 + 侧向分支 | A（1200） |
| 一件事分几步、每步怎么验、错了怎么退 | 流程图 · SOP 步骤流 | 横向序号卡片 + 通过条件行 | B（1960） |
| 多个角色之间消息怎么来回 | 时序交互图 | 顶部角色列 + 纵向时间轴 | A（1200） |
| 一个体系包含什么、怎么分类 | 层次结构图 | 横向树 / 纵向缩进树 | A（1200） |
| 几个方案在若干维度上谁强谁弱 | 对比矩阵 | 表格式网格 | A（1200） |
| 某事从哪天到哪天、有哪些节点 | 时间线 | 横向主轴 + 上下交错节点 | A（1200） |
| 一个对象在哪些状态间流转 | 状态机 | 环形或网格 + 有向边 | A（1000） |

**三种图型混用是常见的失败。** 想同时表达"层间调用"和"时序"时，选信息更重要的那个，
另一个用注释补充；硬塞在一张图里会变成谁也读不懂的意大利面。

**决策流和 SOP 步骤流不要混。** 决策流回答"走哪条路"，节点是判断和结果；
SOP 步骤流回答"按顺序做哪几步"，节点是带序号的动作。混在一起会出现"第 3 步里又分叉
到第 2 步"这种读不下去的结构。

## 二、分区全景图（信息密度最高，模式 B 主力）

骨架直接复制 `006-双栏骨架.svg`。**这是画布模式 B 的典型用图**——信息量大到必须点开看。

```
标题 20 bold                                    ← 左上
数据来源 12 #616161                             ← 标题正下方
                        ┌ 外部实体（胶囊 17 bold）┐   ← 居中偏右，向下分叉
        ↓ 分叉箭头                    ↓
┌ 分区 A ────────────┐          ┌ 分区 B ────────────┐
│ 17 + 副标题 11.5    │          │ 17 + 副标题 11.5    │  rx=12
│ ┌ 区块 ──────────┐ │          │ ┌ 区块 ──────────┐ │
│ │ 14 bold 标题    │ │          │ │ 14 bold 标题    │ │  rx=8 白底
│ │ [卡片][卡片][卡片]│ │          │ │ [卡片][卡片][卡片]│ │  272×82 rx=6
│ └────────────────┘ │          │ └────────────────┘ │
│ ┌ 区块 ──────────┐ │          │ ┌ 区块 ──────────┐ │
│ └────────────────┘ │          │ └────────────────┘ │
└────────────────────┘          └────────────────────┘
┌ 警示 / 结论块（橙底虚线）──────────────────────────┐
└────────────────────────────────────────────────┘
┌ 图例 通栏（两行，色块 22×14）─────────────────────┐
└────────────────────────────────────────────────┘
```

### 卡片三行结构（实测尺寸）

这是全景图的信息载体，**行距固定**，不要平均分布：

| 行 | 内容 | 字号 | 相对卡片顶边 | 颜色 |
|---|---|---|---|---|
| 第一行 | IP / 系统名 / 节点名 | 15 bold | +30 | 跟底色系（蓝底 `#0d2f5c`） |
| 第二行 | 用途 / 归属 | 11.5 | +51 | `#37474f` |
| 第三行 | 补充说明 / 异常 | 11.5 | +69 | `#37474f`，异常用 `#c62828` |

卡片 `272×82 rx=6`，三行基线在 `y0+30 / +51 / +69`。
**行距 21 / 18，不是等距。** 第一行字大所以间距大，后两行同号紧排。

### 坐标参数（1960 画布）

```
分区外框   x=20  w=920  rx=12  fill=#f1f8e9 stroke=#2e7d32
右分区     x=1020（左 +1000，中间留 80 放互联标注）
分区标题   x=分区.x+20   y=分区.y+30   fs=17 bold
分区副标题 x=分区.x+128  y=分区.y+30   fs=11.5   ← 与标题同行，紧跟其后
区块容器   x=分区.x+20  w=880  rx=8  fill=#ffffff stroke=#cfd8dc
区块标题   x=区块.x+16  y=区块.y+25   fs=14 bold（带 emoji）
卡片       x=区块.x+15  w=272  h=82  rx=6
卡片 pitch 289（= 272 + 17），一排 3 张：55 / 344 / 633
```

一排 3 张卡：`15 + 3×272 + 2×17 = 865`，区块宽 880，右边距 15 ✓

### 数量约束

| 约束 | 上限 | 超了怎么办 |
|---|---|---|
| 分区数 | **2 个** | 3 个以上横向放不下，改成分层架构图或拆两张 |
| 每个分区的区块数 | **5 个** | 合并同类区块 |
| 每个区块的卡片数 | **3 张一排**，可多排 | 换行，`y + 卡片高 + 20` |
| 每张卡片的文字行 | **3 行** | 第 4 行说明改放到区块注释行 |

### 常见错误

- 左右两个分区**内容不同就放弃对齐** → 区块的 y 坐标必须一致，读者要横向对比
- 卡片三行平均分布 → 第一行会离顶边太远，视觉上散
- 区块标题和卡片主文字同字号 → 层级塌了，区块标题要 14 且带颜色
- 图例条目比图上实际颜色多 → 套模板最常犯，删元素必须删图例

## 三、分层架构图

纵向排列层，每层内部横排组件。骨架复制 `003-骨架模板.svg`。

```
标题 + 数据来源
外部调用方（胶囊形，居中）
    ↓
┌ 接入层 ─────────────────────────────┐   高 140
│  [枢纽]  [组件]  [组件]              │
└──────────────────────────────────────┘
    ↓ 层间距 36
┌ 业务层 ─────────────────────────────┐
│  [核心]  [模块]  [模块]              │
└──────────────────────────────────────┘
┌ 数据层 ─────────────────────────────┐
│  [主存储]  [缓存]  [预留]            │
└──────────────────────────────────────┘
结论块
图例
```

### 硬性数量约束

| 约束 | 上限 | 超了怎么办 |
|---|---|---|
| 层数 | **5 层** | 合并同类层，或把某层展开成单独一张图 |
| 每层组件数 | **5 个** | 归并次要组件为"其他"，细节另图 |
| 跨层箭头 | **每列 1 条** | 只画代表性流向，平行调用用文字说明 |
| 全图卡片总数 | **15 张** | 拆成"总览 + 分域"两张 |

**层数超过 5 层几乎一定说明这张图想讲的太多。** 典型的四层是：
接入 → 业务 → 数据 → 基础设施。三层（去掉基础设施）更常见。

### 坐标策略

- 模式 A 画布宽 1200，内容区 `x=30` 起，宽 1140，左右页边距各 30
- 每层一个分组底板（`#ffffff` / `#cfd8dc`），**层高固定 140**，层间距 36
- 层高构成：标题 26 + 卡片 76 + 底部留白 20 + 顶部间距 18
- 层内卡片用 002 第二节的组合表（3 张 w=186 / 4 张 w=138 / 5 张 w=110）
- 层标题在底板左上，`x = 底板.x + 16`，`y = 底板.y + 26`，字号 14 bold
- 层间箭头从底板底边中线到下一层顶边 −2

### 配色

| 层 | 卡片色 | 层标题色 |
|---|---|---|
| 接入层 | 外部蓝 `#bbdefb` | `#0d47a1` |
| 业务层 | 主体绿 `#c8e6c9` | `#1b5e20` |
| 数据层 | 扩展紫 `#d1c4e9` | `#311b92` |
| 基础设施 | 次要黄 `#fff9c4` | `#8d6e00` |

**层与层之间的区分靠位置和间距，不靠每层一个新颜色。** 上表的颜色是给层内组件的，
不是"每层必须不同色"。全图枢纽橙最多 2 处（通常是某一层的单点组件）。

### 常见错误

- 每层高度不同 → 图面没有节奏，改等高
- 层内卡片不等宽 → 一眼看出歪，用 pitch 公式统一
- 跨层画满所有调用关系 → 变蜘蛛网，只留代表性流向
- 层标题字号和卡片主文字一样大 → 层级塌了

## 四、网络拓扑图

双栏分区，骨架复制 `006-双栏骨架.svg`。要点：

- 外部实体用胶囊形置顶，向下分叉到各分区
- 左右两个大分区**区块的 y 坐标完全一致**（内容可以不同，位置要对齐）
- 分区间互联用蓝色粗实线双向箭头；间隙 80 放不下标注文字时，语义交给图例
- 分区内按"出口 → 入口映射 → 资源 → 管理面"从上到下排列
- 空置/预留集中放在一个虚线框里，不要散落

**拓扑图的左右两侧通常装不同环境 / 不同分组的同类对象**，所以"卡片数量可以不同，
区块位置必须相同"——照抄右分区时要按区块对齐，不是按卡片数量对齐。

## 五、流程图

流程图有两种形态，**先确认是哪一种**：

| 形态 | 回答什么 | 布局 | 画布 |
|---|---|---|---|
| **决策流** | 走哪条路 | 纵向主线 + 侧向分支 | A（1200） |
| **SOP 步骤流** | 按顺序做哪几步、每步怎么验 | 横向序号卡片 + 条件行 | B（1960） |

### 5.1 决策流

```
        ┌─────────┐
        │  开始   │
        └────┬────┘
             ▼
      ╭──────────────╮  否
      │  判断条件     ├──────────┐
      ╰──────┬───────╯          │
             │ 是                ▼
             ▼             ┌─────────┐
        ┌─────────┐        │ 异常处理 │
        │ 处理步骤 │        └────┬────┘
        └────┬────┘             │
             ▼                  │
        ┌─────────┐             │
        │  结束   │◄────────────┘
        └─────────┘
```

#### 节点形态（照真实做法）

| 节点类型 | 形态 | 配色 |
|---|---|---|
| 开始 / 结束 | 胶囊（rx = 半高） | 外部蓝 `#bbdefb` |
| 处理步骤 | 矩形 `rx=6` | 主体绿 `#c8e6c9` |
| **判断** | **胶囊（rx = 半高）** | 次要黄 `#fff9c4` |
| 异常 / 失败 | 矩形 `rx=6` | 负面红 `#ffcdd2` |
| 结果 · 选中 / 推荐 | 矩形 `rx=6`，描边 2 | 主体·强调 `#a5d6a7` |
| 结果 · 未选 / 备选 | 矩形 `rx=6` | 已下线灰 `#eceff1`（文字 `#546e7a`） |

**判断节点用胶囊，不用菱形，也不用矩形。** 两个理由：

1. 菱形在 240×64 里装不下中文条件，角上还留大片空白
2. **胶囊和步骤矩形一眼能分开**——读者扫一眼就知道"这是分叉点"。用矩形判断框时，
   判断和步骤长得一模一样，得读文字才知道哪里分叉

#### 分支标注

出边标"是 / 否"或具体条件，写在**离节点 8px 的位置**，`font-size 11.5`。
结果型分支直接用橙色文字写出结论，比"是/否"信息量大：

```
→ 方案A：RPM 安装        （橙色 #bf360c，11.5）
→ 方案B：musl 静态二进制
```

#### 坐标策略

- 模式 A 画布宽 1200，主线居中于 `x=600`
- 节点统一宽 **240**，高 **64**，`x = 600 − 120 = 480`；胶囊 `rx=32`
- 纵向 pitch = 节点高 + 间隙，间隙里放箭头：
  - 常规 **46**（箭头 24 + 上下留白）
  - 需要标注文字时 **64**
- 分支节点放在主线右侧，`x = 480 + 240 + 80 = 800`
- **回边统一走右侧固定通道** `x = 800 + 240 + 60 = 1100`，避免与主线、分支重叠

#### 硬性数量约束

| 约束 | 上限 | 超了怎么办 |
|---|---|---|
| 节点数 | **12 个** | 拆成主流程 + 子流程（子流程另起一张） |
| 单个分支深度 | **3 层** | 超过就抽成子流程 |
| 回边数 | **2 条** | 多了说明是状态机不是流程，换图型 |

流程图超过 12 个节点，读者会开始跳着看。**这时候拆图比压缩字号更有效。**

### 5.2 SOP 步骤流

**变更单、迁移方案、上线操作**用这种形态。特点是把"每步怎么算通过、不通过怎么办"
直接写进图里，读者不需要回头查文档。

```
┌ 第 0 步 · 分类判定（先判再动手）───────────────────────┐
│ [黄卡 1] [黄卡 2] [黄卡 3] [黄卡 4]   每张：标题 + 依据 + → 决定 │
└──────────────────────────────────────────────────────┘
┌ 六大步骤  串联 ①②③④⑤⑥，环环相扣 ────────────────────┐
│ ①卡片 → ②卡片 → ③卡片 → ④卡片 → ⑤卡片 → ⑥卡片      │
│   ✅通过    ✅通过    ✅通过    ✅通过    ✅通过      │
│   ❌不通过→  ❌不通过→ ...                          │
└──────────────────────────────────────────────────────┘
┌ 核心结论（橙底虚线）──────┐  ┌ 回滚红线（橙底虚线）──────┐
│ ① …                      │  │ ① …                      │
└──────────────────────────┘  └──────────────────────────┘
图例：绿箭头=正常流向 / 橙虚线箭头=不通过回滚
```

#### 步骤卡片结构

| 部分 | 内容 | 样式 |
|---|---|---|
| 序号 | `①`–`⑥`，独立一行 | `#388e3c`，18 bold，卡片左上 |
| 标题 | 动作名（"导出 conf（只转不改）"） | 15 bold |
| 正文 | 命令 / 参数 / 判断依据 | 等宽 10.5，或 sans 11.5 |
| **通过条件行** | `✅ 通过：xxx` | 浅绿底条（`#e8f5e9`），`#388e3c` 文字，11.5 |
| **失败路径** | `❌ 不通过 → 回滚 xxx` | 卡片下方独立一行，`#bf360c` 11.5 |

**通过条件和失败路径必须成对出现。** 只写通过条件等于没写验收标准——
读者不知道失败时该退到哪一步。

#### 布局参数（1960 画布）

```
步骤卡片数 n ≤ 6，一排横排
卡片宽 = (内容宽 − (n−1)×间隙) / n
n=6 时：宽 300，间隙 20，起点 x=30  →  30 + 6×300 + 5×20 = 1930，右边距 30 ✓
卡片高 = 序号区 32 + 标题 30 + 正文 50 + 通过条件条 34 ≈ 146
卡片下方留 24 放失败路径文字
箭头在两个卡片之间，纵坐标取卡片垂直中心
```

#### 结论块与回滚红线

底部并排两块，**橙色虚线边框**（`#fff3e0` + `#e65100` + `dasharray`），标题 15 bold
用 `#bf360c`，正文 12.5 用 `#5d4037`，序号用 `①` 前缀。

「核心结论」写"这套方案的关键判断"，「回滚红线」写"什么条件下必须退"。
两块都是**给人做决定用的**，不是复述流程。

#### 硬性约束

| 约束 | 上限 |
|---|---|
| 步骤数 | **6 步**（一排放不下就分两排，但超过 8 步该拆成两个 SOP） |
| 每个步骤的正文 | **3 行**（命令/参数最多 3 行，再多写进文档正文） |
| 结论块 | **1–2 个**（核心结论 + 回滚红线，不要第 3 个） |

## 六、时序交互图

顶部一排角色，纵向时间往下走，横向连线表示消息。

```
  [用户]        [网关]        [服务]        [数据库]
    │             │             │             │
    │──① 请求────▶│             │             │
    │             │──② 校验────▶│             │
    │             │             │──③ 查询────▶│
    │             │             │◀──④ 结果────│
    │◀──⑤ 响应────│             │             │
```

### 坐标策略

- 模式 A 画布宽 1200，角色列等距：4 列 `pitch=280`，角色框宽 200，起点 `x=80`
  - 验算：`80 + 3×280 + 200 = 1120`，右边距 80，与左边距 80 对称 ✓
- 每个角色下方一条垂直虚线生命线，从角色框底边到图例上方
  `stroke-dasharray="6 5"`，`stroke="#bdbdbd"`
- 消息水平线 `y` 按序号递增，pitch **56**（有标注时 **70**）
- 消息序号用 `①②③`，写在线的中点上方，`font-size 11.5`
- 激活期（某角色正在处理）用窄矩形叠在生命线上，宽 10，填 `#c8e6c9`，
  **画在消息线之前**（后画的会盖住消息线）

### 常见错误

- 生命线没通到底，读者以为流程中断
- 给每条消息不同颜色 → 序号已经承担区分功能，线统一灰色
- 返回消息和请求消息混在一起 → 返回用橙色虚线区分

## 七、层次结构图

一个根，向下展开。层级浅、每层广用横向树；层级深、每层窄用纵向缩进树。

横向树坐标策略：

- 模式 A 画布宽 1200，根节点居中，宽 **260**，高 **56**，`x=470`
- 子节点按层分排，`y = 根.y + 层序 × 130`
- 层内等距：`pitch = 节点宽 + 40`，整层居中于画布中线
- 连线用**折线**（`<path>` 直角弯），不用斜线——直角能看清归属关系

```xml
<!-- 父节点底边中点 (600,146) → 下降 20 → 水平到子节点中心 (300) → 降到子节点顶边 194-2 -->
<path d="M 600 146 V 166 H 300 V 194" fill="none" stroke="#607d8b" stroke-width="1.5"
      marker-end="url(#arrow)"/>
```

`marker-end` 必须写，否则看不到指向。若采用纯层次包含关系（不是流向），
可以去掉箭头，但要保证线条是灰色实线，与"流向"区分开。

配色：根节点用枢纽橙（根就是焦点），中间层主体绿，叶子用次要黄或空缺灰。

## 八、对比矩阵

本质是把表格画成图。**多数情况下，这种需求用 Markdown 表格比 SVG 更好**——
先问自己一句：读者需要在图上做空间推理吗？不需要就别画。

确实要画时：

- 画布宽 1200，首列（维度名）宽 **200**，其余等宽
- 4 个方案列：(1200 − 2×40 − 200) / 4 = 230
- 行高固定 **56**，表头行高 **48**
- 单元格填色表示评级：优 → `#c8e6c9`、中 → `#fff9c4`、差 → `#ffcdd2`、无 → `#f5f5f5`
- 单元格里**用文字写评级**（优/中/差），不能只有颜色——色盲用户读不出色差
- 若做的是"方案 A vs 方案 B"，**选中的那个用 `#a5d6a7` 加粗描边**，未选的有意灰化
  到 `#eceff1`，读者一眼看出结论

## 九、时间线与状态机

**时间线**：画布宽 1200，横向主轴距顶 **200**，节点上下交错（避免标注重叠），
`x_i = x0 + i × pitch`，pitch 按节点数均分可用宽度。节点用圆形或小胶囊，
标注两行：上行日期（`11.5`，灰）、下行事件（`13`，深）。

**状态机**：画布宽 1000。状态数 ≤ 6 用环形排布，> 6 用网格。
状态框统一 `rx=8`。起始状态加粗描边（`stroke-width=2.5`），
终态用**双线框**：外框 `rx=11`、内框 `rx=8`，两框边缘间距 3（即外框比内框大 6，
同心时 rx 正好差 3）。转移边标注"事件/条件"，`font-size 11.5`，沿边中点外侧偏移 6px。

## 十、不适用的情况

这个 skill **只做结构化示意图**。以下需求不该用它：

| 需求 | 该用什么 |
|---|---|
| 柱状图 / 折线图 / 饼图 / 散点图 | 图表库（ECharts / Chart.js），数据一变就要重算 |
| 有大量数据点的可视化 | 同上 |
| 插画、示意图、封面图 | 图像生成工具 |
| 需要交互（点击展开、悬浮提示） | HTML + CSS，不是 SVG 单文件 |
| 精确到像素的 UI 稿 | 设计工具 |
| 纯文字表格 | Markdown 表格，比画图快且可编辑 |

误用边界的判断标准：**图上的元素数量是"设计出来的"还是"算出来的"**。
设计出来的（框、线、分区）适合手写 SVG；算出来的（几十个数据点）应该用图表库。
