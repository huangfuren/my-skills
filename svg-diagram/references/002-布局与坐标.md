# 布局与坐标

SVG 没有自动布局，**每个坐标都要自己算**。这里是算法，照着套就不会溢出、不会压盖。

画布尺寸先按 `001-视觉规范.md` 第一节确定——**画布定错，后面所有坐标白算**。
本文件的算法与画布宽无关；示例按 1200（模式 A）给，全景图用 1960（模式 B）时的
专属参数见 `005-图型与布局选型.md` 第二节。

## 一、动笔前先写坐标表

在写 SVG 之前，把这张表填完（写在草稿里或直接写成 XML 注释）：

```
画布              1200 × ?（高度最后算）
标题区    x=30  y=42
外部实体  x=400 y=90   w=400  h=54
层1       x=30  y=180  w=1140 h=140    卡片 y=224 h=76
层2       x=30  y=356  w=1140 h=140
层3       x=30  y=532  w=1140 h=140
结论块    x=30  y=700  w=1140 h=100
图例      x=30  y=820  w=1140 h=58
画布高 = 图例底边 878 + 24 = 902
```

**跳过这一步直接写 XML，返工率接近 100%。**

### 标题的 x 怎么定

两种都对，但要和整张图的骨架一致：

- **左对齐（主流）**：`x = 内容左边距`（通常 30），与下方所有容器左边界对齐。信息密度高的图用这个
- **居中**：`text-anchor="middle"`，但要居中到**内容的中心，不是画布的中心**：

```
内容中心 x = (最左元素左边界 + 最右元素右边界) / 2
```

两者只有在内容左右完全对称时才相等。内容不对称时按画布宽的一半去居中，
标题看上去会偏——这是"说不出哪里歪"的常见来源。

### 事后发现左右间距不相等：别改坐标，包一层 g

已经画完了才发现整体偏左或偏右，**不要逐条改 x**。把全部内容包进一个 `<g>`：

```xml
<svg viewBox="0 0 1200 800" font-family="...">
  <defs>...</defs>
  <g transform="translate(22, 0)">
    <!-- 原有内容，坐标一个不动 -->
  </g>
</svg>
```

```
dx = (右边距 − 左边距) / 2
dx > 0 → 内容右移；dx < 0 → 内容左移
```

代价是**文件里的坐标不再等于实际渲染位置**，后续改图要心算偏移。所以：
一次性微调用它，还要继续大改就老老实实改坐标并把 `g` 去掉。
注意居中标题的 `x` 不受 `g` 影响（若标题也在 `g` 内则会一起平移，此时要重算内容中心）。

## 二、等距排列公式

同一排的卡片，**宽度必须一致**，位置用统一步长推：

```
x_i = x0 + i × pitch          （i 从 0 开始）
pitch = 卡片宽 + 间隙
```

排完后必须验算右边界，**且左右内边距要相等**：

```
左边距 = x0 - 容器.x
右边距 = 容器.右边界 - (末张.x + 末张.宽)
左右内边距相等 ⇔ 布局对称
```

只验算"不溢出"是不够的——溢出能看出来，**左右不相等要量才知道**，但视觉上会觉得歪。

### 实测可用组合（620 宽的区块内，内边距 16）

| 卡片数 | 卡片宽 | 间隙 | pitch | 起点 | 末张右边界 | 右边距 |
|---|---|---|---|---|---|---|
| 3 | 186 | 15 | 201 | x0+16 | x0+604 | 16 |
| 4 | 138 | 12 | 150 | x0+16 | x0+604 | 16 |
| 5 | 110 | 10 | 120 | x0+15 | x0+605 | 15 |

表中 `x0` = 区块左边 **x**（如 40）。三行都以区块为基准，可直接横向比较。

### 小卡片组合（588 宽的内层框内，内边距 9）

适用于"空缺 / 预留"这类集中展示区。**这张表的内层框不是区块，不要与上表混用基准。**

| 卡片数 | 卡片宽 | 间隙 | pitch | 起点 | 末张右边界 | 右边距 |
|---|---|---|---|---|---|---|
| 6 | 90 | 6 | 96 | 内框.x+9 | 内框.x+579 | 9 |
| 9 | 58 | 6 | 64 | 内框.x+9 | 内框.x+579 | 9 |

一排放不下就换行（`y + 行高`），**不要为了塞进一排把字号压到 10 以下**。
小卡宽 58 时最多放 4 个中文字，再多要换行或改成一句话说明。

## 三、容器高度计算

```
容器高 = 最后一个子元素底边 − 容器顶边 + 底部内边距
底部内边距 ≈ 20（有说明文字时 ≈ 25）
```

注意"子元素底边"不等于"文字基线"——基线下方还有下降部（descender），
大约再往 `font-size × 0.25`。快速估算时直接用基线即可。

**容差 ±8px。** 按公式算出 261 而实际写 255，视觉上完全看不出来，不用改；
差到 15 以上才会出现明显过挤或过空。

### 改高度的连锁反应

某子元素高度 `+Δ` 时，**四个地方一起改**：

1. 该子元素自身 `height +Δ`
2. 父容器 `height +Δ`
3. 父容器内该元素**下方**所有元素 `y +Δ`
4. 若父容器是顶层，画布 `viewBox` 高与白底 rect 高 `+Δ`

漏改第 2、3 步 → 内容溢出边框；漏改第 4 步 → 底部被裁掉。

### 层与层之间

纵向排列的层（分层架构图），层间距固定 **36**，用来放层间箭头。
层高通常固定（如 140 = 标题 26 + 卡片 76 + 底部 20），这样每层等高，图面有节奏。

**不要每层不同高**，除非内容量确实差很多（差一倍以上），否则等高更好读。

## 四、文字垂直居中

`<text>` 的 `y` 是**基线**，不是顶边也不是中心。

### 单行

```
基线 y ≈ y0 + h/2 + font-size × 0.35
```

例：矩形 `y=557 h=68`，字号 12.5 → 基线 ≈ `557 + 34 + 4.4 ≈ 595`。

### 多行（整体居中）

先算文字块总高，再整体居中，**不要逐行往上堆**：

```
行距 = 上一行 font-size + 6~8
文字块高 ≈ 首行 font-size + Σ行距
首行基线 = y0 + (h − 文字块高)/2 + 首行 font-size × 0.75
第 n 行基线 = 首行基线 + Σ前 n−1 个行距
```

例：卡高 76，字号 15 + 13，行距 21

```
文字块高 ≈ 15 + 21 = 36
首行基线 = y0 + (76−36)/2 + 15×0.75 = y0 + 20 + 11.25 = y0 + 31
第二行基线 = 首行 + 21 = y0 + 52
```

三行时把第三行行距（通常 18~20）加进总高再重算。

### 三行卡片实测值（全景图主力，直接套）

文档库真实图的卡片是 `272×82`，三行基线**不等距**：

| 行 | 内容 | 字号 | 基线 | 相对上行 |
|---|---|---|---|---|
| 1 | IP / 系统名 | 15 bold | `y0 + 30` | — |
| 2 | 用途 / 归属 | 11.5 | `y0 + 51` | +21 |
| 3 | 补充 / 异常 | 11.5 | `y0 + 69` | +18 |

```
y0 = 卡片.y
第一行 30（字大，离顶边留够）
第二三行 21 / 18（同号紧排）
底边余量 = 82 − 69 = 13，正好放下降部
```

**不要三行平均分成 27/27/27。** 第一行字号大、字重粗，平均分会让它贴着顶边走，
视觉上整张卡的重心偏上。

```xml
<rect x="46" y="224" width="358" height="76" rx="6" fill="#c8e6c9" stroke="#2e7d32" stroke-width="1.5"/>
<text x="225" y="255" font-size="15" font-weight="bold" fill="#1b3d1e">【模块名】</text>
<text x="225" y="277" font-size="11.5" fill="#37474f">【职责 · 量级】</text>
```

水平居中用 `text-anchor="middle"`，`x` 取卡片中心 `= rect.x + width/2`。
同排多张卡片统一用 `<g text-anchor="middle">` 包起来，少写一堆重复属性。

## 五、文字宽度预估（防溢出）

渲染前估算，比渲染后返工便宜：

```
中文字符宽 ≈ font-size × 1.0
数字 / 字母 / 点 / 斜杠 / 短横 ≈ font-size × 0.55
```

例：`198.51.100.0/24` 共 15 个 ASCII 字符，字号 11.5
→ `15 × 0.55 × 11.5 ≈ 95px`，卡片宽需 ≥ 103（留 8px 内边距）。

**判据：估算宽度 ≤ 卡片宽 − 8。** 超了就降字号（最低 10）或加宽卡片。
中英混排按两类分别累加。

长标识符（长名称、长路径、长哈希、长表达式）是最常见的溢出来源，
画之前先算一遍，别等渲染出来才发现。

## 六、双栏对称布局（1400 画布）

并列的两个大分区必须严格对称，否则一眼看出歪：

```
画布宽 1400
左分区  x=20    w=660   → 右边界 680
中间留白        40      → 680~720，互联线中心 x=700
右分区  x=720   w=660   → 右边界 1380
两侧页边距各 20
```

两个分区的**内部区块 y 坐标必须完全一致**，读者可以横向对比。
实现方式：**右分区 = 左分区全部内容 x 偏移 +700**，包括每一张卡片。
先写完左分区，再整体偏移复制，比并列着写更不容易出错。

### 中间间隙放不下文字时

40px 的间隙放不下"两分区互联"这类标注（居中排开约 80px，会压到两侧边框）。

**间隙 < 80 时不放文字标注**，只画连线，语义交给图例（如「分区互联（已确认）」）。
间隙 ≥ 80 时才在线上方放两行居中标注。

判断方法：`标注文字估算宽 ≤ 间隙宽 − 8` 才放，否则删。

## 七、连线坐标

### 直线连接两个矩形

```xml
<!-- 从左卡片右边缘到右卡片左边缘，垂直居中 -->
<line x1="300" y1="417" x2="326" y2="417"
      stroke="#607d8b" stroke-width="2" marker-end="url(#arrow)"/>
```

`y` 取两个矩形的共同中心线，`x1` = 左矩形右边界 + 4，`x2` = 右矩形左边界 − 6
（给箭头留出空间，否则箭头尖会插进矩形里）。

### 层间纵向箭头

```xml
<!-- 上层底板底边 320 → 下层底板顶边 354（层间距 36） -->
<line x1="600" y1="320" x2="600" y2="354" stroke="#607d8b" stroke-width="2" marker-end="url(#arrow)"/>
```

终点落在目标层顶边 **−2**，让箭头尖贴着边框而不插进去。

### 斜线从上层节点分叉到下层分区

```xml
<line x1="840" y1="140" x2="440" y2="178" stroke="#607d8b" stroke-width="2"
      marker-end="url(#arrow)"/>
```

### 双向互联

`stroke-width="3"` 必须配 12×12 的大箭头，否则箭头相对线宽太小（见 001 第六节）：

```xml
<line x1="684" y1="436" x2="716" y2="436" stroke="#1565c0" stroke-width="3"
      marker-start="url(#arrowBlueLg)" marker-end="url(#arrowBlueLg)"/>
```

### 曲线箭头：末端方向由 cp2 决定（高频出错点）

`orient="auto"` 让箭头沿着**路径末端的切线**旋转。C/Q 曲线的末端切线由最后一段
「cp2 → 终点」的方向决定，所以 **cp2 放歪，箭头就是斜的**——用眼睛很难判断原因。

```xml
<!-- ❌ cp2 随手放，箭头会斜着指 -->
<path d="M100,100 C 100,200 250,200 300,250" fill="none"
      stroke="#607d8b" stroke-width="2" marker-end="url(#arrow)"/>

<!-- ✅ 让 cp2 与终点共轴，切线自然竖直向下 -->
<path d="M100,100 C 100,200 300,220 300,250" fill="none"
      stroke="#607d8b" stroke-width="2" marker-end="url(#arrow)"/>
```

四方向的 cp2 约束：

| 想要的箭头方向 | cp2 约束 | 写法（终点 ex, ey） |
|---|---|---|
| ↓ 向下 | `cp2.x = ex`，`cp2.y < ey` | `C ...,... ex,ey-20 ex,ey` |
| → 向右 | `cp2.y = ey`，`cp2.x < ex` | `C ...,... ex-20,ey ex,ey` |
| ← 向左 | `cp2.y = ey`，`cp2.x > ex` | `C ...,... ex+20,ey ex,ey` |
| ↑ 向上 | `cp2.x = ex`，`cp2.y > ey` | `C ...,... ex,ey+20 ex,ey` |

规则记一句：**让 cp2 落在终点的正后方 20px 处**，箭头就一定正。

### 绕障走线

路径要绕开阻挡元素时，贴障距离至少留 20，否则线看起来是擦着框过去的：

```xml
<!-- 需绕过的框右边界 620，绕行通道走 x=650 -->
<path d="M600,313 Q 650,313 650,400 Q 650,640 635,685" fill="none"
      stroke="#e65100" stroke-width="2" stroke-dasharray="5 4"
      marker-end="url(#arrowOrange)"/>
```

## 八、图例（必须有）

固定放画布底部，**通栏宽度**（与画布同宽或左右各留 20）。

### 尺寸参数（实测）

| 项 | 值 |
|---|---|
| 色块 | `22 × 14`，`rx=3` |
| 文字 x | 色块 x + 32 |
| 行距 | 26（两行图例） |
| 文字字号 | 12，颜色 `#37474f` |
| 外框 | `#ffffff` / `#bdbdbd`，`stroke-width=1`，**直角不加 rx** |
| 外框高 | 单行 65、双行 70（含上下各 15 内边距） |

### 列距按画布宽定

```
条目数 n，分两行时每行列数 c = ceil(n/2)
列距 pitch = (画布宽 − 2×40) / c
条目 i 的色块 x = 40 + (i mod c) × pitch
条目 i 的文字 x = 色块 x + 32
第一行色块 y = 图例.y + 15，第二行 +26
```

例：1960 画布、8 个条目 → `c=4`，`pitch=(1960−80)/4=470`，色块 x = 40 / 510 / 980 / 1450。

**列距不要写死。** 条目少的时候（5–6 项）铺满一行更好看；条目多就分两行。
同一张图的图例必须**左右顶到 40 与画布宽 −40**，不能挤在左边。

### 图例条目必须与图上元素一一对应

- 图上没有的颜色不许出现在图例
- 图上有的必须在图例里能查到
- 删了某类元素，图例对应条目同步删
- **箭头样式也要进图例**（正常流向 / 不通过回滚），流程类图的读者靠它区分走哪条路

**例外：容器色不进图例。** 只列"分类色"（卡片 / 节点的填充色），不列"容器色"：

| 不列 | 理由 |
|---|---|
| 顶级分区外框 `#f1f8e9` | 通栏大框，位置就说明了它是分区 |
| 分组底板 `#ffffff` | 白底是默认，不需要解释 |
| 结论块 `#fff3e0` | 位置固定在底部，靠位置识别 |
| 外部实体胶囊 `#eceff1` | 图里通常只有一个，形状独特 |

这些靠**形状和位置**就能识别，列进图例反而占位置。校验时看到"图上有、图例无"
先判断它是不是容器色，是就跳过。

这条是硬规则，最容易在"套模板"时被忽略——模板里的图例是为模板的元素配的，
你删了元素却不删图例，就是错误信息。
