# 校验清单

**结构合法 ≠ 画面正确。** 三道关都要过：XML 结构、渲染目视、文案残留。

## 一、三道关的命令

```bash
# 第一关：结构层（脚本一次查 12 项）
python scripts/check_svg.py images/xxx.svg

# 第二关：渲染成 PNG（各平台方案见下），然后打开目视
# 第三关：残留旧文案与占位符排查
grep -n "待确认\|待补录\|未记\|未知\|TODO\|【" images/xxx.svg || echo "无残留"

# 检查完清理临时目录
```

第一关的 `scripts/check_svg.py` 查这些：XML 可解析、`&` 转义、字体栈（首位实体字体 + 含 Noto）、
色值是否在 001 登记、元素越出画布、卡片溢出容器、字号档位、marker 属性与线宽配套、
文字溢出卡片、图例与元素对应、成排卡片左右内边距对称、白底 rect。

`--json` 出机器可读结果，`--palette <路径>` 指定别的色卡。
**它查不出语义错误**——图有没有表达对意思、层级是否清楚、重点是否突出，只能目视。

第二关的产物必须**打开看**，不能因为命令退出码为 0 就认为通过。

### 各平台渲染方案

| 平台 | 命令 | 前提 |
|---|---|---|
| macOS | `qlmanage -t -s 1200 -o /tmp/svgchk xxx.svg` | 系统自带，无需安装 |
| Linux | `rsvg-convert -w 1200 xxx.svg -o /tmp/out.png` | `apt install librsvg2-bin` |
| 任意（Python） | 见下方脚本 | 需 `pip install cairosvg` |
| 任意（浏览器） | 直接拖进浏览器打开 | 无，**最接近用户真实所见** |

### Windows / 通用：cairosvg 三个必踩的坑

**坑一：`convert` 不是 ImageMagick。** Git Bash 下敲 `convert` 会命中
`C:\Windows\system32\convert.exe`——那是 FAT→NTFS 磁盘转换工具，与图片无关。别敲。

**坑二：字体栈首个字体必须是本机实体字体，否则整段中文变方块。**

实测（Windows + cairosvg 2.9.1）：cairosvg 遇到列表里第一个字体不存在时**不会继续回退**，
整段文字直接渲染成方块。三种写法对比：

| 字体栈写法 | 结果 |
|---|---|
| `-apple-system,'PingFang SC','Microsoft YaHei',sans-serif` | **全方块**（6308 B） |
| `'PingFang SC','Microsoft YaHei','Noto Sans CJK SC',sans-serif` | **全方块**（6308 B，和上一行一模一样） |
| `'Microsoft YaHei','PingFang SC','Noto Sans CJK SC',sans-serif` | **正常**（21474 B） |

所以**只把中文字体"补进列表末尾"是不够的，必须让它排在第一个**。
`001-视觉规范.md` 第一节已经把这个顺序定死，按它写就不需要任何渲染前替换。

**旧图兼容**：接手用旧字体栈（`-apple-system` 打头）的图时，渲染前替换一次：

```python
# render_legacy.py —— 仅用于旧图，新图不需要
import cairosvg, pathlib, sys

src = pathlib.Path(sys.argv[1] if len(sys.argv) > 1 else "images/xxx.svg")
raw = src.read_text(encoding="utf-8")
patched = raw.replace(
    "-apple-system,'PingFang SC','Microsoft YaHei',sans-serif",
    "'Microsoft YaHei','PingFang SC','Noto Sans CJK SC',sans-serif",
)
cairosvg.svg2png(bytestring=patched.encode("utf-8"),
                 write_to="check.png", output_width=1200)
print("rendered -> check.png")
```

Windows 上 `python3` 可能没有 cairosvg，用装了它的解释器绝对路径：

```bash
PY="C:/Users/Lenovo/.workbuddy/binaries/python/envs/default/Scripts/python.exe"
"$PY" -c "import cairosvg; print(cairosvg.__version__)"   # 先确认有依赖
"$PY" render_legacy.py images/xxx.svg
```

**坑三：emoji 在 cairosvg 下不渲染。** 表现为空白框或直接缺失，这是 cairosvg 的能力限制，
不是图的缺陷。**不要为了"让 emoji 显示出来"去改图**。要确认 emoji 效果，用浏览器打开 SVG。

### 推荐做法：浏览器为主，cairosvg 为辅

- **最终验收用浏览器**：那才是读者实际看到的效果，字体、emoji、圆角全部真实
- **迭代过程用 cairosvg**：快，能在终端里连续渲染对比
- 两者结论冲突时，**以浏览器为准**

### 必须做一次缩放验证

图最终会被缩放显示。渲染时**按目标显示宽度再渲一张**，确认最小字号仍可读：

```bash
# 假设图要嵌进 800px 宽的正文
python3 -c "
import cairosvg, pathlib
raw = pathlib.Path('images/xxx.svg').read_text(encoding='utf-8')
cairosvg.svg2png(bytestring=raw.encode('utf-8'), write_to='check_800.png', output_width=800)
"
```

打开 `check_800.png`，如果最小那行字看不清，**说明画布定大了**，回去改画布宽，
不要靠放大字号硬撑（放大字号会溢出卡片）。

## 二、目视检查清单

渲染出 PNG（或浏览器打开）后逐项过，**不许跳项**：

### 可读性（先查这条，不通过就重画）

- [ ] 画布模式与读者行为匹配（A 内嵌即读 1200/1400；B 全景查阅 1960 且确认读者会点开）
- [ ] 模式 A 按 800px 显示宽度缩放后，最小字号仍 ≥7px
- [ ] 字号未低于下限（模式 A ≥11，模式 B ≥10）
- [ ] 字号只从 001 第四节那 11 档里取，没有 13.3 / 11.7 这类随手值
- [ ] 同一语义层在图内尺寸一致（所有卡片副文字同一个号）

### 文字

- [ ] **文字里的 `&` `<` `>` 已转义**——未转义会让整个文件解析失败、浏览器白屏，这是唯一会让图"完全消失"的错误
- [ ] 卡片内文字没有超出卡片边框（尤其长标识符：长名称、长路径、长哈希、长表达式）
- [ ] 说明文字没有超出所在区块右边界
- [ ] 没有文字互相压盖
- [ ] 没有文字压在连线或箭头上
- [ ] 中文没有出现豆腐块（字体栈首个字体须是本机实体字体，且必须含 `Noto Sans CJK SC`）
- [ ] 多行文字整体居中，不是贴顶堆叠

### 容器与布局

- [ ] 每个子元素都完整落在父容器内，没有溢出边框
- [ ] 区块之间没有互相压盖
- [ ] 画布底部没有裁掉内容（图例是否完整可见）
- [ ] 画布底部没有大片空白（`viewBox` 高度是否该收缩）
- [ ] 并列分区左右对称，高度和内部区块 y 坐标对齐
- [ ] 同排卡片宽度一致、间距均匀，**左右内边距相等**（不能只验"不溢出"）
- [ ] 层与层之间间距统一
- [ ] 层级靠位置和间距区分，没有靠"每层换个颜色"来区分

### 连线

- [ ] 箭头指向正确的目标，没有插进矩形内部
- [ ] 箭头颜色与线同色（marker 的 fill 与 line 的 stroke 一致）
- [ ] 双向箭头两端都有箭头（`orient="auto-start-reverse"` 写了没）
- [ ] **marker 声明了 `markerUnits="userSpaceOnUse"`**——漏写会让箭头随线宽翻倍
- [ ] **线宽 ≥2 时换了大号 marker**（7×7 只配 stroke-width ≤1.5；2~2.5 用 10×10，3 用 12×12）
- [ ] **曲线末端的箭头方向正确**（末段 cp2 与终点共轴，否则箭头斜着指）
- [ ] 实线 / 虚线的语义正确：已确认用实线，待确认用虚线
- [ ] 线宽只有 1 / 1.5 / 2 / 2.5 / 3 五档
- [ ] 中间间隙放不下标注文字时，没有硬塞（改由图例表达）

### 内容正确性

- [ ] 图例条目与图上实际元素一一对应，没有多余也没有缺失
- [ ] 已确认的信息没有再标"待确认 / 待补录 / 用途未记"
- [ ] 用户要求删除的内容彻底删了（图形 + 所有相关文案 + XML 注释）
- [ ] 同一条信息在卡片 / 区块注释 / 结论块 / 图例 / 副标题里表述一致
- [ ] 数量统计与实际画出的卡片数吻合（如"共 11 个空缺"就要真有 11 张卡）
- [ ] 数据来源与截止日期已写在标题下方
- [ ] 模板占位符 `【】` 全部替换掉了
- [ ] 配色只用了语义表登记的颜色，没有临时新增色值
- [ ] **文字色取自 001 第三节的文字表，没有拿配色表的 `stroke` 色当文字色**（橙卡用 `#e65100` 只有 2.56:1，看不清）
- [ ] 枢纽橙、风险红各不超过 2 处

### 图型专项

| 图型 | 额外要查 |
|---|---|
| 分区全景 | 左右分区区块 y 坐标完全一致；卡片三行基线 +30/+51/+69 不等距；图例条目与图上颜色一一对应 |
| 分层架构 | 层数 ≤5、每层组件 ≤5、全图卡片 ≤15；层高一致；跨层箭头每列 ≤1 条 |
| 网络拓扑 | 双分区区块位置对齐；间隙 <80 时中间不放文字 |
| 决策流 | 节点 ≤12；判断用**胶囊**（rx=半高）且与步骤矩形一眼可分；出边标"是/否"；回边走右侧固定通道不穿主线 |
| SOP 步骤流 | 步骤 ≤6；每步"通过条件"与"失败路径"成对出现，缺一不可；箭头样式进图例 |
| 时序图 | 生命线通到画布底部；序号连续无跳号；激活期矩形画在消息线之前 |
| 层次结构 | 连线用直角折线且带 `marker-end`；同层节点垂直对齐 |
| 对比矩阵 | 单元格有文字评级，不只是纯色块（色盲可读） |
| 状态机 | 终态双线框同心（外框 rx 比内框大 3，不是 2） |

### 落盘

- [ ] 存在目标文档同级 `images/` 目录（或用户指定位置）
- [ ] 命名符合 `YYYYMMDD-HHMMSS-mmm.svg`，或单独交付时用语义命名
- [ ] 文档用相对路径引用，且路径真实可达（`test -f` 验证过）
- [ ] 临时渲染文件已清理

## 三、常见画面缺陷与成因

| 现象 | 成因 | 修法 |
|------|------|------|
| 文字溢出卡片右边 | 未按 `font-size × 0.55`（ASCII）估算宽度 | 降字号或加宽卡片，重算 pitch |
| 内容溢出区块底边 | 改了子元素高度但没改父容器 height | 父容器 `+Δ`，下方同级元素 `y +Δ` |
| 底部内容被裁 | 元素超出 `viewBox` 高度 | `viewBox` 与白底 rect 高度同步加大 |
| 底部大片空白 | 删了内容但没收缩画布 | 收缩 `viewBox` 与白底 rect |
| **图嵌进文档后字太小** | **画布宽超过用途所需** | **缩画布宽，不要放大字号** |
| 箭头尖插进方框里 | 终点坐标没给箭头留空间 | 终点回退 4~6px |
| 双向线只有一端有箭头 | 缺 `orient="auto-start-reverse"` | 补到 marker 定义上 |
| 箭头和线断色 | marker 的 fill ≠ line 的 stroke | 统一色值 |
| **整张图白屏 / 一片空白** | **文字里有未转义的 `&` `<` `>`，XML 解析失败** | **转义为 `&amp;` `&lt;` `&gt;`，见 001 第九节** |
| 深色模式下看不见文字 | 缺白底 rect | 补全画布尺寸的白底 rect |
| 中文豆腐块 | 字体栈首个字体不是本机实体字体（如 `-apple-system` 打头）；或漏了 `Noto Sans CJK SC` | 按 001 第一节的字序写，`Microsoft YaHei` 打头 |
| cairosvg 渲染出空方框 | 该字符是 emoji，cairosvg 不支持 | 用浏览器复核，不要改图 |
| 箭头忽大忽小 | 漏写 `markerUnits="userSpaceOnUse"`，或粗线没换大 marker | 补属性；线宽 ≥2 换 10×10 / 12×12 |
| 曲线末端箭头歪斜 | 末段 cp2 没和终点共轴 | 让 cp2.x 或 cp2.y 等于终点坐标，见 002 第七节 |
| 某排卡片挤在一起 | 卡片宽不一致或 pitch 算错 | 统一卡片宽，重算 `x_i = x0 + i × pitch` |
| 两侧内边距不等 | 只验了"不溢出"，没验对称 | 重算起点使左右内边距相等 |
| 删掉元素后留下空洞 | 只删了元素没重排剩余元素 | 剩余卡片重算 pitch，或相邻区块拉宽占位 |
| 图例有图上不存在的颜色 | 删元素时漏删图例条目，或套模板没改图例 | 同步删图例 |
| 多行文字偏上/偏下 | 逐行累加而没有整体居中 | 用 002 第四节的多行公式重算 |
| 画面脏、说不出哪不对 | 圆角档位太多，或字号出现中间值 | 圆角按元素类型固定，字号只从 001 第四节那 11 档里取 |

## 四、改图专项自查

改完已有 SVG，额外过这几条：

- [ ] 改动量 > 5 处或涉及位移时，用了**整文件重写**而不是连续局部替换
- [ ] 重写前**完整读过**当前文件，以文件实际内容为准（不凭记忆）
- [ ] 用 `grep` 确认旧表述零残留（含 XML 注释里的）
- [ ] 一处语义改动，同步改了全部 5 个可能位置：
      卡片文字 / 区块注释 / 结论块 / 图例 / 分区副标题 / XML 注释
- [ ] 删区块后处理了留下的空白区域
- [ ] 改完重新渲染目视，没有只跑 XML 校验就交付
