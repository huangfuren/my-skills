# 视觉规范

配色、字号、箭头一律照本文件抄，不要每张图重新发明。同一套语义色跨图复用，
读者看过一张图就认得下一张。

> 数值来源：主流技术文档库 116 个在用的 SVG 实测统计（字号 4386 处、色值全量、
> 圆角与线宽逐元素）。**不是设计推导，是实际用法归纳。** 与行业无关——
> 软件架构、业务流程、数据管道、项目管理用的是同一套色与同一套字号。

## 一、先定画布尺寸

画布有两个可行模式，**选错模式的后果不同**：

| 模式 | 画布宽 | 读者行为 | 最小字号 | 用在 |
|---|---|---|---|---|
| **A · 内嵌即读** | **1200**（宽图 1400） | 直接看正文，不点开 | **11** | 操作手册、变更单、SOP、决策流程、评审材料 |
| **B · 全景查阅** | **1960** | **会点开看大图** | **10**（标题禁低于 9.5） | 系统全貌、对象总览、跨域关系梳理 |

### 怎么选

问一句：**这张图是"看一眼就懂"，还是"对着它查"？**

- 读者要按图操作 → 模式 A。图里出现"点击第 3 步""按此配置"这类动作，字必须当场看清
- 读者要拿它查某个节点在哪 / 盘点全部对象 → 模式 B。信息量本身就大，压到 1200 只能删信息

**不要默认 1960，也不要默认 1200。** 多数返工来自"没想清楚读者会不会点开"。

### 换算关系

```
实际显示字号 = 设计字号 × (显示宽度 / 画布宽度)
```

正文区约 768–900px（不同渲染器略有差异）。按 800 反推：

| 画布宽 | 缩放比 | 设计字号 11 实际显示 | 设计字号 9.5 实际显示 |
|---|---|---|---|
| 1200 | 0.67 | 7.4px 可读 | 6.4px 勉强 |
| 1400 | 0.57 | 6.3px 偏小 | 5.4px 不可读 |
| 1960 | 0.41 | **4.5px 不可读** | **3.9px 不可读** |

**这张表说明模式 B 的前提是"读者会点开"。** 如果图会被嵌进正文却不保证点开，
就必须走模式 A——否则文字再规范也没用。

模式 B 的额外要求：**主信息（名称、标识符、步骤标题）字号 ≥ 13**，
只让注释行降到 10。全图都靠 10 号字撑，点开也累。

### 基础写法

```xml
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 1200 800"
     font-family="'Microsoft YaHei','PingFang SC','Noto Sans CJK SC',sans-serif">
  <rect x="0" y="0" width="1200" height="800" fill="#ffffff"/>
```

- `viewBox` 定尺寸，**不写** `width` / `height` 属性，让图随容器自适应缩放
- 必须有白底 `rect`，尺寸与 `viewBox` 一致——否则深色模式下文字会看不见
- 若 `viewBox` 的 x/y 不是 0 0，白底 rect 要跟着偏移；**建议统一用 0 0**
- **文本里出现 `&` `<` `>` 必须转义**，否则整张图解析失败、白屏。见第九节

#### 字体栈：为什么这样排（实测结论，别改顺序）

```
'Microsoft YaHei'  → Windows 命中
'PingFang SC'      → macOS 命中
'Noto Sans CJK SC' → Linux / 容器 / 服务端渲染命中
sans-serif         → 兜底
```

三条硬约束：

1. **不能漏 `Noto Sans CJK SC`。** Linux 环境（容器、CI、服务器端转换）没有前两个字体，
   漏了就是整图中文豆腐块。
2. **首个字体必须是本机实体字体，不要用 `-apple-system`、`system-ui` 这类通用族名打头。**
   实测：cairosvg 在 Windows 下遇到首个字体不存在时**不会继续回退列表**，整段文字直接变方块。
   `-apple-system` 打头和 `'PingFang SC'` 打头渲染出来都是全方块，只有 `Microsoft YaHei`
   打头才正常。这条同样适用于 rsvg 一类简陋渲染器。
3. **顺序按"哪台机器先命中"排，不是按审美排。** macOS 上没有 Microsoft YaHei 会自动跳到
   PingFang SC，视觉结果一致；反之在 Windows 上 PingFang SC 不存在，很多渲染器就直接放弃了。

### 同一颜色的两种用法（别混淆）

真实图里绿色和橙色各承担两种角色，按**元素性质**区分，不是按颜色：

| 颜色 | 当它是"节点/卡片"时 | 当它是"标记/文字"时 |
|---|---|---|
| 绿 `#c8e6c9` | 主体组件、正常态 | ✅ 通过 / 已满足（文字用 `#388e3c`） |
| 橙 `#ffcc80` | 枢纽、关键节点 | ❌ 不通过 / 警示 / 失败路径（文字用 `#bf360c`） |
| 灰 `#eceff1` | 已废弃、未选备选 | 待确认、无数据 |

**对比类图里，绿 = 推荐/选中，灰 = 备选/未选。** 这是读者最容易直觉理解的一组。

### 怎么把语义分配到元素上

三步，不要边画边想：

1. **先定主导语义**——这张图要回答的核心问题是什么（"谁连着谁"用主体绿做底，
   "数据怎么流"用外部蓝做起点，"哪里有问题"用风险红做焦点）
2. **再给每个元素贴一个角色**——宁可归到"主体"，也不要临时发明新颜色。
   同一角色元素数超过 3 个，说明该考虑分组建底板了
3. **橙色和红色最后分配，且限量**——枢纽色与风险色是全图的视觉焦点，
   各超过 2 处等于没有焦点

**禁止临时添加色值。** 表里 16 条不够用时，优先复用语义最接近的一条，或者拆分底板，
而不是引入第 17 种颜色。新增色值会让这套配色失去跨图一致性。

### 对比度：描边色不能当文字色（实测）

这套配色是「填充 / 描边 / 文字」三元组，**三者不可互换**。最常犯的错是图省事拿
`stroke` 色当文字色，实测后果：

| 误用 | 对比度 | 判定 |
|---|---|---|
| 橙卡文字用描边色 `#e65100` on `#ffcc80` | **2.56:1** | ✗ 远低于正文 4.5 |
| 黄卡文字用描边色 `#f9a825` on `#fff9c4` | **1.84:1** | ✗ 几乎看不清 |
| 绿卡文字用描边色 `#2e7d32` on `#c8e6c9` | 3.81:1 | ✗ 不达标 |
| 蓝卡文字用描边色 `#1565c0` on `#bbdefb` | 4.09:1 | ✗ 不达标 |

按上表正确取值时全部达标（最低 4.81:1）：

```
绿卡 #123314 on #c8e6c9 → 10.35   橙卡 #7f3f00 on #ffcc80 → 5.43
蓝卡 #0d2f5c on #bbdefb →  9.48   紫卡 #311b92 on #d1c4e9 → 7.51
黄卡 #7f3f00 on #fff9c4 →  7.50   红卡 #7f0000 on #ffcdd2 → 7.84
```

**规则：文字色只从上表取，不要从配色表的 `stroke` 列取。** 低于 4.5:1 的正文文字
在投影、缩放、打印场景下会糊成一团。序号 ① ② ③ 用 `#388e3c` 是 4.12:1，
按"图形/大字"标准（≥3:1）合格，但不要用它写正文。

## 四、字号层级

**语义 4 层，尺寸按卡片宽度细分。** 这两个维度要分开看：语义层决定"谁比谁重"，
尺寸档决定"这一层在具体宽度下能塞几个字"。

| 语义层 | 尺寸 | 用途 | 字重 |
|---|---|---|---|
| ① 标题层 | **20** | 图名 | bold |
| ② 分区层 | **17** | 分区名、外部实体 | bold |
| ③ 内容层 · 大卡 | **15** | 卡片主文字（宽 ≥240）、结论块标题、步骤标题 | bold |
| ③ 内容层 · 区块 | **14** | 区块容器内的小组标题（带 emoji 那一行） | bold |
| ③ 内容层 · 中卡 | **13** | 卡片主文字（宽 140–240） | bold |
| ④ 正文层 | **12.5** | 结论块正文、说明段 | — |
| ④ 正文层 | **12** | 数据来源、截止日期、图例条目 | — |
| ④ 注释层 · 主 | **11.5** | 卡片第二三行、分区副标题、分支标签 | — |
| ④ 注释层 · 密 | **11** | 小卡（宽 <140）内的文字、密集清单 | — |
| ④ 注释层 · 微 | **10** | 第三行补充、箭头标注、计数 | — |
| ④ 注释层 · 极限 | **9.5** | **仅模式 B（1960）可用**，模式 A 禁用 | — |

规则：

- **只能从这 11 档里选**，不允许 13.3、11.7、10.8 这种随手值。跨图一致靠固定档位实现
- **同一语义层在同一张图内必须同尺寸**——这是真约束。尺寸个数不是约束
- 卡片主文字选 15 / 13 / 11，看的是**卡片宽度**（≥240 / 140–240 / <140），不是重要程度
- **模式 A 最小 11，模式 B 最小 9.5。** 低于下限说明信息太多，该拆图
- 层级差异靠字号 + 字重 + 颜色三者叠加，不要只靠字号

> 为什么不是"全图只有 4 种字号"：真实技术图里，一个 272 宽的卡片装标识符、一个 138 宽的
> 卡片装模块名，用同一尺寸必然有一边溢出或另一边浪费。**约束的是语义层数（4 层）
> 和档位必须来自固定表，不是尺寸个数。**

## 五、技术标识用等宽字体

IP、端口、哈希、路径、命令、配置项、版本号这类**需要逐字符比对**的内容，用等宽字体。

```xml
<text x="218" y="165" font-size="10.5" fill="#7f3f00"
      font-family="ui-monospace,Menlo,Consolas,monospace">10.29.249.124  10.29.249.125</text>
```

字体栈固定：`ui-monospace,Menlo,Consolas,monospace`

### 什么时候用

| 内容 | 字体 | 理由 |
|---|---|---|
| 单个标识符作卡片主文字 | 常规 sans + bold | 视觉重量更重要，等宽反而显小 |
| 卡片内 **2 个以上标识符的清单** | **等宽** | 末位对齐，扫读时能快速定位 |
| 命令 / 参数 / 配置路径 / 代码片段 | **等宽** | 与正文区分，避免被当成说明文字 |
| 版本号、端口号连着写 | **等宽** | `:8080`、`v0.42.0` 这类容易看错 |
| 中文说明、系统名 | 常规 sans | 等宽中文字距过宽，占地方 |

**等宽字号比同层常规文字小 0.5–1**（如副文字 11.5，则等宽用 11 或 10.5），
因为等宽字符本身偏宽，同字号会更挤。

**不要全图用等宽**——等宽只用于"需要对齐的短标识"，正文一律 sans。
真实图里等宽占比约 2%（102/4386），这个比例可以参考。

## 六、箭头 marker

固定三种，放在 `<defs>` 里：

```xml
<defs>
  <marker id="arrow" viewBox="0 0 10 10" refX="9" refY="5"
          markerWidth="7" markerHeight="7" markerUnits="userSpaceOnUse"
          orient="auto-start-reverse">
    <path d="M 0 0 L 10 5 L 0 10 z" fill="#607d8b"/>
  </marker>
  <marker id="arrowBlue" viewBox="0 0 10 10" refX="9" refY="5"
          markerWidth="7" markerHeight="7" markerUnits="userSpaceOnUse"
          orient="auto-start-reverse">
    <path d="M 0 0 L 10 5 L 0 10 z" fill="#1565c0"/>
  </marker>
  <marker id="arrowOrange" viewBox="0 0 10 10" refX="9" refY="5"
          markerWidth="7" markerHeight="7" markerUnits="userSpaceOnUse"
          orient="auto-start-reverse">
    <path d="M 0 0 L 10 5 L 0 10 z" fill="#e65100"/>
  </marker>
</defs>
```

- `orient="auto-start-reverse"` 是双向箭头的前提，必须写
- **`markerUnits="userSpaceOnUse"` 必须写。** 不写时默认 `strokeWidth`，箭头尺寸会随线宽
  放大——线宽 2 时箭头直接翻倍，撑破预留间隙
- marker 的 `fill` 要和线的 `stroke` 同色，否则箭头和线断色
- 需要第四种颜色时，复制一份改 `id` 和 `fill`，不要复用不同色的 marker
- 流程主线用 `stroke-width="2"`；**大流程图（模式 B）主箭头可到 2.5–3**，让方向更醒目

### 粗线必须换大箭头（否则头重脚轻）

上表 7×7 的箭头是给 `stroke-width ≤ 1.5` 用的。线加粗到 2 以上时，小箭头看起来像
一个点缀而不是指向，视觉上方向感消失。

| 线的 stroke-width | marker 尺寸 | refX | 终点回退量 |
|---|---|---|---|
| ≤ 1.5 | 7×7（上表） | 9 | 4–6 |
| **2 ~ 2.5** | **10×10** | **9** | **7–8** |
| **3** | **12×12** | **10** | **9–10** |

```xml
<!-- 配 stroke-width="3" 的双向互联箭头 -->
<marker id="arrowBlueLg" viewBox="0 0 10 10" refX="9" refY="5"
        markerWidth="12" markerHeight="12" markerUnits="userSpaceOnUse"
        orient="auto-start-reverse">
  <path d="M 0 0 L 10 5 L 0 10 z" fill="#1565c0"/>
</marker>
```

**「终点回退量」的来历**：箭头尖会超出线段终点约 `markerWidth × 0.7`，回退不够箭头就
插进目标框里。回退量按上表取，比自己估更省事。

### 线宽语义

| stroke-width | 用于 |
|---|---|
| **1** | 分组底板、图例外框、空缺虚线框 |
| **1.5** | 卡片常规描边、图例色块（**使用频率最高**） |
| **2** | 分区外框、外部实体、一般连线、主流程箭头 |
| **2.5** | 最高亮卡片（枢纽）、关键连线 |
| **3** | 已确认的双向互联、模式 B 的主流程箭头 |

不要出现 0.5 / 1.2 / 3.5 这类值。线宽与语义绑定后，读者能从粗细判断元素性质。
线宽 ≥2 时记得按上一节换大箭头。

### 线型语义

| 关系 | 写法 |
|------|------|
| 一般流向 / 调用 / 依赖 | `stroke="#607d8b" stroke-width="2" marker-end="url(#arrow)"` |
| 已确认的双向关系 | `stroke="#1565c0" stroke-width="3" marker-start="url(#arrowBlueLg)" marker-end="url(#arrowBlueLg)"` |
| 正常流程推进 | `stroke="#388e3c" stroke-width="2" marker-end="url(#arrowGreen)"` |
| 失败 / 回滚 / 不通过路径 | `stroke="#e65100" stroke-width="2" stroke-dasharray="5 4" marker-end="url(#arrowOrange)"` |
| 可达范围 / 逻辑关系 / 影响面 | `stroke="#e65100" stroke-width="2" stroke-dasharray="5 4" marker-end="url(#arrowOrange)"` |
| 故障 / 异常链路 | `stroke="#c62828" stroke-width="2" stroke-dasharray="4 3"` |
| 待确认关系 | 灰虚线 `stroke="#9e9e9e" stroke-dasharray="6 4"`，并在旁标注"待确认" |

**实线 = 已确认，虚线 = 待确认或逻辑关系。** 一旦确认要把虚线改成实线。

流程类图里**箭头颜色也要进图例**：「正常流向」绿箭头、「不通过 / 回滚」橙虚线箭头——
读者靠线的样式区分走哪条路，靠图例学会这个约定。

## 八、圆角（按元素类型固定）

圆角不承载语义，只区分元素类型。**同类元素必须同圆角**，不要按"重要程度"自由取值。

| 元素类型 | rx | 实测依据 |
|---|---|---|
| 胶囊（外部实体 / 判断节点） | 高度的一半（h=54→27、h=52→26，必须严格等于半高） | — |
| 顶级分区外框 | 12 | 104 个矩形用 rx=12，宽中位 920，均为分区级 |
| 分组底板 / 区块容器 | 8 | 399 个，宽中位 880，均为容器级 |
| 卡片 | 6 | 940 个，宽中位 250 高 59，均为卡片级 |
| 小卡片（空缺 / 次要） | 4 | — |
| 图例色块 | 3 | — |
| 图例外框 | 0（直角） | 真实图为通栏直角框，不是圆角卡 |

一张图最多出现 6 档，且必须与上表对应。不出现的类型不占档位。

间距见 `002-布局与坐标.md`。

## 九、XML 特殊字符（写之前必看）

SVG 是 XML。文字里有未转义的 `&` `<` `>`，**整个文件解析失败，浏览器直接白屏**——
不是显示错，是什么都不显示。这是唯一一类会让图"完全消失"的错误，也是最容易漏的。

| 字符 | 必须写成 | 什么时候会遇到 |
|---|---|---|
| `&` | `&amp;` | 名称里的"与"、`R&D`、`AT&T`、查询串 `?a=1&b=2` |
| `<` | `&lt;` | 比较表达式 `x < 10`、泛型 `List<String>` |
| `>` | `&gt;` | 比较表达式 `x > 0`、箭头文字 `->` |
| `"` | `&quot;` | 属性值内部（文本节点里可留） |
| `'` | `&apos;` | 属性值内部（文本节点里可留） |

```xml
<!-- ❌ 这两行会让整图白屏 -->
<text x="40" y="60">Load & Save</text>
<text x="40" y="80">QPS > 1000 正常</text>

<!-- ✅ 转义后 -->
<text x="40" y="60">Load &amp; Save</text>
<text x="40" y="80">QPS &gt; 1000 正常</text>
```

### 用脚本生成 SVG 时，必须先转义

从表格、数据库、接口、文件名等外部来源取来的文字，拼进 SVG 之前一律过一遍转义。
**最容易踩的来源**：团队名（含 `&`）、需求描述（含 `<>`）、用户输入、文件名。

```python
def svg_escape(s):
    return (str(s).replace("&", "&amp;").replace("<", "&lt;")
                   .replace(">", "&gt;").replace('"', "&quot;"))

svg += f'<text x="40" y="60">{svg_escape(team_name)}</text>'
```

### 自查

```bash
# 有输出 = 可能有未转义字符，逐个确认
grep -n '&[^a-z#]' images/xxx.svg | grep -v '&amp;\|&lt;\|&gt;\|&quot;\|&apos;'
```

另外两条会让解析失败的写法：XML 注释里出现 `--`（`<!-- a -- b -->` 非法），
以及同名属性写两遍（`<rect fill="a" fill="b"/>`）。
