# SVG 作图规范

在文档库中用手写 SVG 画信息密度较高的架构图 / 拓扑图。**不依赖任何绘图工具或第三方库**，
纯文本可 diff、可 review、可被后续 AI 精确修改，这是选 SVG 而不是截图或 draw.io 的根本原因。

**核心原则：先算坐标，再写代码；改完必渲染，渲染必目视。**

## 标准工作流程

### 第一步：确认信息源与口径

动笔前必须明确：

- **数据来自哪里**（哪张表、哪篇文档、哪次巡检结果），图上要写明来源与截止日期
- **哪些信息已确认、哪些待确认**——待确认的要么标注清楚，要么先问用户，不要凭感觉画
- **本图的边界**（例如"仅含服务器侧，办公侧另出一张"），避免范围蔓延

不确定的信息**问用户，不要编造**。图会被当成权威资料引用，编造的连线和网段危害极大。

### 第二步：分层列清实体与关系

把要画的东西按层次列出来，先文字后图形：

```
外部（互联网）
  └─ 边界（公网出口 / 防火墙）
      └─ 入口映射（DNAT → 内网服务）
          └─ 内部资源（服务器网段 / 容器网段 / 管理网段）
关系：机房间互联、跨层可达范围
```

分层清楚了，坐标自然就有了。**没分层就直接画，一定会返工。**

### 第三步：规划坐标网格（关键，不可跳过）

在写第一行 SVG 之前，把画布尺寸、每个区块的 x/y/宽/高、卡片的排列间距**算出来写下来**。
详见 `references/002-布局与坐标.md`，核心三条：

1. **等距排列**：`x_i = x0 + i × pitch`，其中 `pitch = 卡片宽 + 间隙`，同排卡片宽度必须一致
2. **容器高度 = 最后一个子元素底边 − 容器顶边 + 底部内边距（约 20）**
3. **并列区块严格对称**：左块 `x=20 w=920`、右块 `x=1020 w=920`，中间留 80 给互联连线

### 第四步：按固定顺序写 SVG

```
<svg viewBox> → 白底 rect → <defs> 箭头 marker → 标题+数据来源
  → 外部节点 → 主体分区（左、右）→ 跨区关系连线 → 汇总说明块 → 图例
```

配色、字号、marker 定义直接抄 `references/001-视觉规范.md`，骨架直接复制
`references/003-骨架模板.svg`，不要每次重新发明配色。

### 第五步：校验 + 渲染 + 目视检查

**这一步不能省，也不能只做前半段。**

```bash
# 1. 结构合法性
python3 -c "import xml.dom.minidom; xml.dom.minidom.parse('images/xxx.svg'); print('SVG 结构合法')"

# 2. 渲染成 PNG（macOS 自带，无需装依赖）
mkdir -p /tmp/svgchk && qlmanage -t -s 1500 -o /tmp/svgchk images/xxx.svg

# 3. 用图片查看工具打开 /tmp/svgchk/xxx.svg.png 目视检查
# 4. 检查完清理
rm -rf /tmp/svgchk
```

目视检查逐项对照 `references/004-校验清单.md`。**结构合法 ≠ 画面正确**：
XML 解析通过但文字溢出卡片、区块互相压盖、容器装不下内容，都只能靠渲染看出来。

### 第六步：落盘与引用

图片落盘与命名约定：

- 存到**文档同级** `images/` 目录，禁止仓库根目录大一统图片目录
- 命名 `YYYYMMDD-HHMMSS-mmm.svg`（时间戳到毫秒）
- 文档中用相对路径引用：`![网络拓扑](../../images/20260803-184500-000.svg)`
- 引用前确认相对路径真实可达（`test -f`）

## 修改已有 SVG 的专项规则

改图比新建图更容易出错，这几条是实际踩出来的：

### 改动量大就整文件重写

超过 5 处修改，或涉及布局位移，**直接用整文件重写**，不要连续几十次局部替换。
局部替换次数多了容易漏改、容易互相冲突，也容易在会话中断后丢失改动。
重写前先完整读一遍当前文件，以文件实际内容为准，**不要凭记忆重写**。

### 一处语义要同步改所有位置

同一条信息在图上通常出现在 4~5 个地方，改一处必须全改：

| 位置 | 例子 |
|------|------|
| 卡片内文字 | `★ 特殊 LB · 联通线上线下` |
| 区块内注释行 | `★ 203.0.113.10 是打通分区 A ↔ 分区 B 的专线网关` |
| 底部汇总块 | `★ 线上线下互通的特殊 LB` |
| 图例条目 | `管控枢纽 / 特殊 LB 网段` |
| 机房副标题 | `业务 192.0.2.0/24 段 · 管理 198.51.100.0/24 段` |
| XML 注释 | `<!-- D 管理网段 -->` |

改完**必须全局 grep 查残留旧表述**：

```bash
grep -n "旧表述1\|旧表述2\|待确认\|待补录" images/xxx.svg || echo "无残留"
```

### 信息确认了就不许再标"待确认"

用户一旦说明了某项用途/关系，图上所有"待确认""待补录""用途未记""信息未知"
的相关标注都要立刻删掉，包括 XML 注释里的。**留着就是错误信息。**

### 删元素要处理留下的空洞

删掉一个卡片或整个区块后：

- 同排剩余卡片要重新计算 `pitch` 均匀铺开，或相邻区块拉宽占位
- 父容器高度、后续同级元素的 y 坐标要相应收缩
- 画布 `viewBox` 高度和白底 rect 高度一起改
- 图例里对应的颜色条目如果不再出现在图上，也要删

### 改高度要连带算父容器和后续元素

某个子元素高度 `+Δ`：父容器高 `+Δ`，其下方所有同级元素 y `+Δ`，
必要时画布高度 `+Δ`。漏了就会出现内容溢出容器边框。

## 硬性禁止

- ❌ `<style>` 标签、外部 CSS、`@font-face` / 网络字体——渲染环境不一定支持
- ❌ `<foreignObject>`、嵌入 HTML——多数 Markdown 渲染器不支持
- ❌ 绝对路径引用、外链图片资源
- ❌ 编造未经确认的网段、IP、连线关系
- ❌ 只校验 XML 结构就交付，不渲染目视
- ❌ 把图片放到仓库根目录统一图片目录
