# 消息语言风格指南

风格样本来源：团队真实群消息留存语料（已脱敏，占位符含义见 SKILL.md「脱敏约定」一节）。
核心判断：**口语开场 + 结构化骨架**。读起来像人说话，扫起来像文档。

---

## 一、六大风格特征

### 1. 按接收对象分块（最重要）

一段消息 = 若干「投递块」，每块以 `@` 对象开头，块之间空行分隔。

```
@所有人
……全员要知会的事……

@成员A
……只要这个人执行的两件事……

@成员B
……另一个人的任务……
```

要点：

- 同一条消息里可以同时存在 `@所有人`（知会）和 `@某人`（指派）
- 先全员后个人，先结论后细节
- 每块只说跟这个对象相关的事，不串台

### 2. 编号体系（三套，按正式程度选）

| 体系 | 写法 | 适用场景 |
| ------ | ------ | --------- |
| 大写中文 | `一、背景` `二、方案` `三、执行进度` | 大段落标题，正式长文、项目同步 |
| 中文序数 | `第一：` `第二：` `第三：` | 分派任务、口语化列举 |
| 阿拉伯数字 | `1、` `2、` 或 `1. 2. 3.` | 执行步骤、清单、并列要点、确认方式 |

规则：

- 同一层级**只许用一套**，不许混用
- 执行步骤用 `1、` 且**动词开头**（`先把信息逆向摸清楚`），不用名词短语
- 并列项句式尽量一致（都是动宾 / 都是名词短语）

### 3. 【】方括号标注关键实体

凡是**需要被眼睛抓住**的东西，一律用【】包起来：

```
【<N> 台】有效库：<N> 个 P0 生产集群（<N> 台）+ 1 个 P1 测试集群（<N> 台）
将该批监控迁至我方自有 Prometheus【<主控 IP>】
采用【per-host + Consul 动态注册】（沿用现有模式）
当前处于【第 1-2 步】
预计下下周
```

高频标注对象：IP / 主机名、方案名、job 名、数量、状态、时间节点、结论段标题。

用作段落小标题时也用【】：
`【问题现象】` `【本机侧排查已完成】` `【结论】` `【初步判断】` `【请协助】`

### 4. 量化优先，消灭模糊词

| ❌ 不要写 | ✅ 要写成 |
| ---------- | ---------- |
| 处理了大部分 | 总计 76 条｜已处理 58 条｜剩余 18 条 |
| 进度还行 | 【<项目名>进展】85% |
| 快好了 | 恢复时效由 4-5 天压缩至当天 |
| 花了一些钱 | 直接成本 0 元，资源投入约 1 万元已节省 |
| 尽快 | 今天下午下班之前 / 明天 15:00 前 |

数字与单位之间统一加空格（`21 台`、`4-5 天`、`约 1万元` 视语境）。
变动要写成算式：`变动：链路总量+3条，完成量+13条，待处理 18 条`。

### 5. 时间锚点必须落地

每个动作都挂一个可核对的时间：
`今天15:00` `<会议室名>` `预计下下周` `明天` `今天下午下班之前` `9 月初`
没有明确时间就写 `待定`，不许留空不提。

### 6. 括号补充，语气收口

用括号承载"防误解"信息，避免正文变长：

```
（不要一上来就关停）
（沿用现有模式）
（网络隔离后，实在依赖太多的话，就最低限度的只保障线上不出问题……）
（只要经手你"过手一遍的信息"，都需要存档可查）
```

开场/收口常用口语：
`各位老板` `老板们` `小伙伴们中午好` `感谢` `辛苦支持下` `麻烦确认下` `如有突发情况，请及时联系运维同学`

## 二、排版细则

- **分隔线**：`==========` 用于大块分界（日期切分、公告头尾），不用于普通段落之间
- **空行**：块与块之间 1-2 个空行；编号项之间不空行，保持紧凑
- **冒号**：`第一：` 用全角冒号；`1.` 用半角点+空格
- **并列分隔**：同级并列可用 `｜`（`总计73条｜已处理45条｜剩余28条`）
- **列表符号**：同级并列项一律用 `1、` `2、` `3、` 数字编号，禁止用 `-` 或 `·` 作为列表符号；即使是无先后顺序的罗列也统一用数字编号，保持可读性。**最多只用两层**：一级段落标题用 `一、` `二、`，层内并列项用 `1、` `2、`，不要引入 `（一）（二）`、`（1）（2）`、`1.` 等更深层级
- **标题行**：项目名 + 百分比同行写 —— `【XXX 项目进展】85%`
- **链接**：单独一行给出，前面加一句说明它是什么
- **长度**：整条消息控制在手机一屏半到三屏；超过三屏就拆成多条（按接收对象拆）

## 三、写作四步法

1. **定对象** — 这条消息给谁？全员知会还是具体某人执行？据此切块
2. **定结论** — 一句话说清"什么事 / 什么状态 / 要对方做什么"，放最前
3. **定骨架** — 从 `formats.md` 选一种格式套
4. **定量** — 把每个模糊词换成数字或明确时间点；把每个待办挂上 @人和截止点

**红线**：只整理、不编造。原文没有的数字、时间、结论，一律不补；缺就标 `待确认`。
