# 输出格式库（7 种）

先选格式再动笔。**选错格式就换**，不要在同一格式里硬塞。

## 选型决策

| 你要表达的核心 | 用哪种 |
|---------------|--------|
| 全员知会一件事的来龙去脉 | ① 群播报式 |
| 把活分给具体几个人 | ② 指派式 |
| 出了故障/异常，要同步 + 求援 | ③ 排障同步式 |
| 周期性汇报项目走到哪了 | ④ 进度同步式 |
| 信息很少，一件事一句话 | ⑤ 极简要点式 |
| 跨多天的碎片流水 | ⑥ 时间线式 |
| 要人拍板 / 有备选方案 | ⑦ 决策建议式 |

---

## ① 群播报式（全员知会）

适用：生产变更公告、方案说明、需要全员知晓的进展。

```
@所有人

【<主题>】

一、背景
<为什么做这件事，1-3 句>

二、方案
<怎么做，关键实体用【】标注>

三、执行进度（N 步）
1、<步骤1> → <步骤2> → <步骤3>
当前处于【第 X 步】。

四、需协调（N 处待确认）
【1、<事项>】<一句话说明> —— @<负责人> <一句话诉求>
【2、<事项>】<一句话说明> —— @<负责人> <一句话诉求>

五、确认方式
【1、<验证点>】<结果>
【2、<验证点>】<结果>
【3、<验证点>】<结果>
<验证/通知/解除依赖>

<相关链接，一行一个>
```

## ② 指派式（分派任务）

适用：直接给人派活。一人一块。

```
@<姓名>

<一句话背景/结论>

第一：<任务>
第二：<任务>
第三：<任务>

注意：<容易踩的坑 / 额外要求>

<截止时间>
```

## ③ 排障同步式

适用：问题上报、求援、排查结论同步。顺序固定：**现象 → 已排查 → 结论 → 判断 → 需要什么**。

```
【问题现象】
1、<可观测的表象>

【<本侧>排查已完成】
1、<查了什么>：<结果>

【结论】：<一句话定性>

【初步判断】
<最可能的原因，可给 2 个候选并排序>

【请协助】
1、<需要对方做什么>
2、<需要对方做什么>
```

## ④ 进度同步式（周/日维度）

适用：周期性汇报，含数字对比。

```
【<项目名>进展】<NN>%

上周：总计 X 条｜已处理 Y 条｜剩余 Z 条
本周：总计 X 条｜已处理 Y 条｜剩余 Z 条
变动：<算式，如 链路总量+3条，完成量+13条，待处理 18 条>

重点疑难
1. <难点>
2. <难点>

特殊规则
假设：<前提>
那么：<推论>

依赖说明：<谁依赖谁>
可选方案：
1、<方案A>
2、<方案B>
```

## ⑤ 极简要点式

适用：信息量小、只需知会，套大骨架反而啰嗦。

```
<一句话结论>

1、<要点>
2、<要点>
3、<要点>

<如有需要 @ 的人或时间节点，单行附在最后>
```

## ⑥ 时间线式

适用：多天/多次的碎片记录汇总成一条。

```
==========
<YYYY-MM-DD>

<当天结论一句话>

- <事项>
- <事项>

==========
<YYYY-MM-DD>

<当天结论一句话>

- <事项>
```

## ⑦ 决策建议式

适用：需要老板/负责人拍板，含成本收益。

```
@<决策人>

<问题一句话>

1、处理方式：<方案>
2、直接成本：<金额>
3、资源投入：<人天/金额>
4、恢复时效：<对比，如 由 4-5 天压缩至当天>
5、业务保障：<对业务的影响>

建议：<倾向哪个方案，为什么>

需决策：<要对方回答什么>
```

---

## 换格式规则（重要）

生成后必须自检，出现下列任一情况**立即换格式重出**：

| 症状 | 处置 |
|------|------|
| 填不满骨架，整段只有干巴巴两三行 | 降级到 ⑤ 极简要点式 |
| 一条消息里塞了 3 个以上不相关主题 | 按主题拆成多条，各自选格式 |
| 有多个明确责任人 | 改 ② 指派式，一块一个人 |
| 有数字但没对比 | 改 ④ 进度同步式，补上周/本周对比 |
| 通篇没有 @、没有时间点 | 补；补不出来就说明原文缺信息，标 `待确认` 并回问用户 |
| 用户说"太长""看不懂""不是这个意思" | 直接换一种格式重出，并在落盘文件里同时保留两个版本 |

换格式时**不要删信息**，只换组织方式。
